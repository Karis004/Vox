# 可调时间与多按钮晨报固件（2026-10-11）

2026-10-11版本。用户已授权固件源码和配套后端统一推送GitHub／部署服务器；部署结果见项目handoff。主板仍是旧短测程序，新功能需重新接线并上传本固件。

解压 `release/vox-daily-buttons-firmware.zip`，Arduino IDE打开daily_briefing/daily_briefing.ino，选择Arduino Leonardo及串口。同目录五个.h一起保留；SoftwareSerial、EEPROM均为Arduino自带库，不需安装按键库。**先改下表按钮接线、核对按键编号，再正式使用**。ESP和语音板沿用成功线路。

## 按键和时间

| 按钮 | 功能 |
| --- | --- |
| 8 | 重置本地校时及待播状态，重新校时；保留已保存的播报时间，不是重启整块主板 |
| 7 | 随时补听网页已保存的完整晨报（包括启用的新闻、天气等）；播放中不叠加 |
| 6 | 进入小时设定，从0开始；第一次按下为1点，此后每次+1，24次回到0点 |
| 1（小时阶段） | 确认小时，立即保存HH:00，进入分钟阶段 |
| 5（分钟阶段） | 每次+5分钟，0→5→…→55→0 |
| 1（分钟阶段） | 保存最终HH:MM，退出设定 |
| 1（平时） | 朗读当前每天播报时间 |
| 2、3、4 | 暂无功能，串口仍显示按键编号 |

例：6号按7次→1号→5号按4次→1号，保存每天香港07:20。只按6号7次→1号，则立即保存07:00；可再按1号退出，或30秒不操作自动退出。未确认的小时或分钟草稿超时丢弃；已经确认的HH:00不会丢。

时间为每天重复的24小时制香港时间。默认07:15，EEPROM地址0～4保存签名、版本、小时、分钟及校验；只在确认且内容变化时写，断电／8号重新校时不清除。改时间无需重新上传。调到今天已经过去或恰好到达的时刻，下一次为明天；需要马上听就按7号。没有RTC或持久化播放进度，上电必须先成功联网校时。

设定期间暂停新的联网和定时播报；每次按键有防抖，长按不连续增加，多键同时按不接受。按键须按下、完全松开再按下一次。语音依次提示小时、分钟、已保存时间，快速连按只保留最新提示，避免声音叠加。30秒设定超时按最后已确认时间恢复工作。

8号／x只停止后续段落，已发给语音模块的当前一段仍会读完。晨报进行中不接受改时间，先按8号停止后续段落再设定；7号在设定中退出草稿并请求补听，保留已经确认的时间。网络请求期间扫描按键并缓存事件，等请求结束再处理，不在HTTP收包中嵌套请求。

## 语音辅助

| 操作／状态 | 语音示例 |
| --- | --- |
| 8号 | “正在重新校时，请稍候”；成功后“校时完成。每天7点20分播报” |
| 校时失败 | “校时暂未成功，正在等待网络，稍后重试”；不会误说已校时 |
| 7号、稿子已准备好 | 直接读晨报，播放中再次按下不叠加 |
| 7号、没有稿子／尚未校时 | 提示晨报正在准备／正在校时，继续自动等待与重试 |
| 6号、5号 | “小时7点”“分钟20分”，快速连按播最新数值 |
| 1号确认小时 | “已保存为每天7点整。五号设分钟，一号确认” |
| 1号确认分钟 | “已保存为每天7点20分” |
| 步骤不符／30秒超时 | 提示先确认小时／保留已保存时间 |

语音提示沿用现有UTF-8 TTS帧，不依赖未验证的蜂鸣命令。整点自动校时保持安静，8号主动校时才提示结果。网络等待和正在播放的当前语音帧会使按键反馈延后；按键仍扫描和缓存，声音不重叠。语音模块没有完成回传，反馈速度与实际读速需要接线上传后听测。

## 新增按钮接线

按无源两列四行矩阵端子L1/L2和R1/R2/R3/R4接线。8号=L2/R4已由用户确认。代码编号假设左列自上而下1～4、右列自上而下5～8，7号在8号上方；其余编号必须在实际板上核对。

**先拔掉旧的L2→GND线，将L2改接D8。按钮板的这六根线都是信号线，不再单独接GND。** R4→D4保留。切勿把语音板的D6挪给按钮。

| 按钮板端子 | Leonardo端子 |
| --- | --- |
| L1 | D7 |
| L2 | D8（替换原GND接线） |
| R1 | D9 |
| R2 | D10 |
| R3 | D11 |
| R4 | D4（原线保留） |

串口115200，逐个按实体1、5、6、7、8，应分别输出 `[KEY] 1/5/6/7/8`。编号不符则先调整keypad.h的KEY_NUMBERS，不把猜测编号当成已实测接法。串口也可输入数字1～8代替按键，t等同7号，s看状态，x停止后续播放。

## 网站配合与补听

40.233.65.88:8086，普通HTTP。上电自动校时、以后整点每小时校时；请求 `/device/time?mode=daily&hour=保存小时&minute=保存分钟`。保存新时间后本地立即重排下一次，联网后同步服务端预热窗口。

新版服务端根据最近一次daily校时请求，提前5分钟准备稿子，持续检查至计划后15分钟；默认为07:10～07:30，支持跨午夜。仅一块主板，服务器重启后默认07:15，直到下次主板校时更新；无论是否预热，`/device/briefing`任何时刻都能触发按需生成。

7号先取manifest；未准备好返回503，主板语音提示“晨报正在准备，请稍候”，每30秒重试，同一等待过程不会每次重复提示；准备好再按固定id逐段请求，每段最多180 UTF-8字节。新闻／AI可能要几十秒或更久，补听不是保证按下即出声。当天相同保存配置且快照有效时复用；超过3小时、日期变化或网页保存新配置则重新生成，不保证下午仍是早上逐字相同的一稿。不会读取未保存网页编辑。

语音没有回传，等待每字符450ms+1500ms为保守估算。断网同一段30秒重试；服务器重启快照失效可能从第一段重播。首次校时已经到／超过设定时刻，等次日，当天补听按7号。
